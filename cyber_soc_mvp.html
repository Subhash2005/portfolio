AI-Powered SOC - MVP Overview

1. Core Concepts & Terminology

  • SOC (Security Operations Center): A centralized function within an organization employing people, processes, and technology to continuously monitor and improve an organization's security posture while preventing, detecting, analyzing, and responding to cybersecurity incidents.
  • Threat Intelligence (Threat Intel): Evidence-based knowledge, including context, mechanisms, indicators, implications, and actionable advice, about an existing or emerging menace or hazard to assets.
  • Impossible Travel Anomaly: A security concept used to detect potentially compromised accounts by identifying when a user logs in from two geographically distant locations within a time frame that is physically impossible to travel between.
  • OSINT (Open-Source Intelligence): The collection and analysis of data gathered from open sources to produce actionable intelligence, often used to identify known malicious IP addresses or bad actors.
  • Vector Database: A database designed to store and query high-dimensional vectors. In this context, it is used for semantic search over threat intelligence data.
  • Knowledge Graph (Graph DB approach): A way of representing data as nodes and edges to understand relationships. Used here to map users to IP addresses and devices to identify anomalous connections.
  • Real-time Event Streaming: The continuous transmission of log data as it is generated, allowing for immediate analysis and threat detection.

2. Technology Stack & Frameworks

Backend Technologies

  • Language: Python 3
  • Framework: FastAPI - A modern, fast web framework for building APIs with Python.
  • Server: Uvicorn - An ASGI web server implementation for Python.
  • WebSockets: Used for establishing a persistent, bidirectional communication channel between the backend and the frontend dashboard to push real-time alerts.

Frontend Technologies

  • Languages: HTML, CSS, JavaScript (Vanilla)
  • Architecture: Real-time dashboard that consumes WebSocket streams to dynamically update tables and alert cards.

3. Models & Specialized Tools

  • LLM (Large Language Model): Google Gemini 2.5 Flash - Acts as the core "AI Agent" that reasons over suspicious logs, analyzes context, and recommends mitigation actions.
  • Vector DB: ChromaDB - An open-source vector database used to store and retrieve relevant threat intelligence.
  • Graph Processing: NetworkX - Used to build a graph of relationships between users, IPs, and devices.

4. MVP Workflow

  • Log Generation/Ingestion: System generates or ingests simulated login logs (User, IP, Location, ISP, Device).
  • Initial Triage (Rule-Based): Checks memory store for past sessions. Detects "impossible travel" or anomalous ISP.
  • Context Enrichment: Queries ChromaDB for relevant threat intelligence based on the suspicious event.
  • AI Analysis: Log, context, and threat intel are sent to Gemini 2.5 Flash.
  • Decision & Action: LLM returns structured JSON indicating threat status, reasoning, and actions.
  • Real-Time Broadcast: Confirmed threats broadcasted via WebSockets to the dashboard.
  • Memory Update: Updates session cache and relationship graph with new data points.
